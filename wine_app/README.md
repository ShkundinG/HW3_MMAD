# Wine Quality — интерактивный сервис рекомендаций

Автор: Шкундин Глеб. Домашнее задание №3 по машинному обучению и анализу данных.

Приложение показывает вероятность того, что экспертная оценка вина не ниже 7/10, позволяет изменять порог рекомендации и исследовать компромисс между precision и recall. Модель и предобработка обучены в ноутбуке заранее; приложение **не обучает модель**.

## Состав проекта

- `app.py` — приложение Streamlit с четырьмя вкладками.
- `model.joblib` — готовый обученный пайплайн `StandardScaler` + `LogisticRegression`.
- `config.json` — порог, выбранный по валидационной выборке.
- `test.csv` — отложенная тестовая выборка для отображения метрик.
- `requirements.txt` — зафиксированные версии зависимостей.

## Запуск локально

Рекомендуемая версия Python: **3.13** (модель сохранена с `scikit-learn==1.8.0`; эта версия также закреплена в зависимостях).

```bash
cd wine_app
python -m venv .venv
```

На Windows:

```powershell
.venv\Scripts\activate
python -m pip install -r requirements.txt
streamlit run app.py
```

На macOS / Linux:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Если запускать из родительской папки, достаточно выполнить `streamlit run wine_app/app.py` после установки зависимостей.

## Возможности

1. **Оценка одного вина.** Ввод 12 признаков: 11 численных лабораторных характеристик и тип вина. Для численных полей диапазоны и значения по умолчанию вычисляются из `test.csv`.
2. **Модельные метрики.** Матрица ошибок, precision, recall, F1, ROC-AUC, PR-AUC и точки текущего порога на ROC/PR-графиках.
3. **Пакетное предсказание.** CSV с названиями всех 12 признаков; добавляются `probability_good` и `recommend`, результат можно скачать. При отсутствующих столбцах приложение показывает понятную ошибку.
4. **Что выучила модель.** Отсортированные коэффициенты логистической регрессии после масштабирования.

## Почему кэширование устроено так

`st.cache_resource` применяется к загрузке `model.joblib`, потому что модель — тяжёлый объект, который безопасно разделять между повторными запусками Streamlit. `st.cache_data` применяется к данным, конфигурации и прогнозным вероятностям тестовой выборки: такие результаты сериализуются и возвращаются из кэша, а приложение не должно повторно вычислять их при каждом изменении порога. Аргумент `_model` в `get_test_probabilities` не хешируется. От перемещения слайдера меняются только бинарные решения и вычисленные из них метрики. Если вызывать `joblib.load` без декоратора, при каждом взаимодействии модель будет снова считываться с диска, увеличивая время отклика и затраты на операции ввода-вывода.

## Публикация на Streamlit Community Cloud

1. Загрузите весь проект в GitHub-репозиторий `ShkundinG/HW3_MMAD`, сохранив папку `wine_app` (включая `model.joblib`).
2. Перейдите на https://share.streamlit.io/ и авторизуйтесь через GitHub.
3. Выберите **Create app**, репозиторий `ShkundinG/HW3_MMAD`, ветку `main` и **Main file path: `wine_app/app.py`**.
4. Установите Python **3.13** в **Advanced settings** и нажмите **Deploy**.
5. После развёртывания проверьте все четыре вкладки и загрузку примерного CSV.

Публикация требует доступа к аккаунтам GitHub и Streamlit Community Cloud. Приложение подготовлено для неё, но публикация не выполнялась автоматически.

## Примечания к методике

Из исходных данных удалены точные дубликаты **до** разделения на обучение и тест, чтобы идентичные наблюдения не попали одновременно в обе выборки. Все параметры масштабирования и коэффициенты модели получены только по обучению; порог выбран по внутренней валидации тренировочной выборки. Тестовая выборка используется для оценки уже выбранного решения.
